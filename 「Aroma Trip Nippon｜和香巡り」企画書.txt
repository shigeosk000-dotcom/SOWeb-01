1　プロジェクト概要
　サービス名：Aroma Trip Nippon｜和香巡り

　コンセプト：
キャッチコピー（15字以内）：日本の香りを巡る旅

サービス説明（50〜100字）：
日本各地の天然素材を使い、自分だけの香りを作る体験型サービス。旅の思い出を香りに閉じ込め、帰国後もオンラインで再購入可能。東京観光の特別なひとときを提供します。

ターゲットユーザー：
① SNS発信型トラベラー
年齢層：20代後半〜30代前半
職業：マーケ職／インフルエンサー／フリーランス
このサービスを使う理由：
日本らしい“特別な体験”をコンテンツとして発信したい。自分だけの香り＝ストーリー性があり、SNS映えするため。
主な利用シーン：
東京観光中に予約して来店。体験中の様子や完成品をInstagram・TikTokに投稿。

👉 拡散力が高く、ブランド認知を広げてくれる最重要層

② 体験重視のカップル旅行者
年齢層：20代後半〜30代
職業：会社員（欧米・アジア圏の都市部）
このサービスを使う理由：
観光地巡りだけでなく、思い出に残る“二人だけの体験”を求めている。ペアで香りを作ることで旅の記念になる。
主な利用シーン：
デートプランの一つとして予約。体験後に香りをお土産として持ち帰る。

👉 満足度が高く、口コミ評価（レビュー）を残しやすい層

③ リピート志向の文化体験層

職業：専門職（医療・教育・ITなど）

解決すべき課題

① 体験ワークショップの予約数低迷
現状の問題点：
認知不足や魅力の伝達不足により、観光プランの選択肢に入らず予約につながっていない。特に訪日外国人への訴求が弱い。
本サービスでの解決アプローチ：
「香り×日本体験」を明確化したコンセプトと多言語対応Webで、観光プランとして選ばれる導線を強化。

② 新しいWeb導線の不足
現状の問題点：
既存チャネル（店舗・紹介など）に依存し、訪日前に予約できる接点が少ないため機会損失が発生している。
本サービスでの解決アプローチ：
SEO・SNS連携・予約機能を備えたWebサイトを構築し、訪日前から予約可能な導線を確立。

③ 体験価値の可視化不足
現状の問題点：
香り体験の魅力が言語化・ビジュアル化されておらず、「何ができるのか」「どんな価値があるのか」が伝わりにくい。
本サービスでの解決アプローチ：
ストーリー設計（香りで日本を巡る）や体験プロセスの可視化により、期待値を高め予約につなげる。

④ 口コミ・拡散の弱さ
現状の問題点：
体験後のシェア導線が設計されておらず、満足度が高くてもSNSやレビューへの投稿につながりにくい。
本サービスでの解決アプローチ：
SNS投稿を前提とした体験設計（映える演出・ハッシュタグ設計）で、自然な拡散を促進。

⑤ 継続購入（リピート）の仕組み不足
現状の問題点：
体験後の関係が一度きりで終わりやすく、帰国後の再購入やブランド接点が途切れてしまう。
本サービスでの解決アプローチ：
EC連携やマイフレグランス管理により、体験後も継続的に購入・接点を持てる仕組みを構築。

まとめ（構造）
①② → 集客・導線の課題
③④ → 体験価値・拡散の課題
⑤ → LTV（継続収益）の課題




3　提案するソリューション

サービスの特長
競合と差別化するサービスの特長を3つ

① 香りで巡る日本体験
説明（50〜80字）：
日本各地の天然素材をテーマに、地域ごとの香りを組み合わせて作る体験型サービス。単なる調香ではなく、日本を巡るストーリー性を提供。

ユーザーにとってのメリット：
観光体験としての満足度が高まり、“思い出を持ち帰れる”特別な体験になる


② 自分だけの香りを継続できる仕組み
説明（50〜80字）：
体験で作成した香りデータを保存し、帰国後もECで同じ香りを再購入可能。単発体験で終わらない継続的な関係を構築。

ユーザーにとってのメリット：
旅の記憶を日常で再体験でき、気に入った香りをいつでも再現・購入できる


③ SNSでシェアしたくなる体験設計

説明（50〜80字）：
制作プロセスや完成品が映える空間・演出を設計し、SNS投稿を自然に促進。拡散されやすい体験価値を意図的に設計。

ユーザーにとってのメリット：
思い出を共有できるだけでなく、特別な体験として周囲に発信できる満足感が得られる


まとめ（差別化の軸）

体験の深さ → ストーリー性（①）
体験後の価値 → 継続購入（②）
拡散力 → SNS設計（③）

👉 多くの競合が「その場体験で終わる」のに対し、
“体験→記憶→拡散→再購入”まで設計している点が強みです。

Webアプリケーション（サーバーサイド）の範囲
制作するWebアプリケーションの機能概要

① 予約管理機能
機能名：予約管理
概要：来店日時、人数、体験コース、予約状況を一覧で確認・変更できる機能。空き枠管理やキャンセル対応も行う。
優先度：Must
② 顧客情報管理機能
機能名：顧客管理
概要：氏名、国籍、連絡先、利用履歴、購入履歴などを管理し、来店時の案内や再購入対応に活用する。
優先度：Must
③ 香りレシピ管理機能
機能名：香りレシピ管理
概要：ユーザーが体験で作成した香りの配合データを保存・検索し、再制作やEC再注文に利用できるようにする。
優先度：Must
④ 商品・在庫管理機能
機能名：在庫管理
概要：香料、容器、ハンドクリーム素材などの在庫数を管理し、欠品防止や発注判断に役立てる。
優先度：Must
⑤ EC注文管理機能
機能名：注文管理
概要：体験後の再購入注文を管理し、注文状況、配送先、発送状況、決済状況を確認できる機能。
優先度：Must
⑥ 多言語対応管理機能
機能名：多言語対応管理
概要：予約確認メール、案内文、管理画面の一部を多言語で表示・管理し、訪日外国人対応を円滑にする。
優先度：Should
⑦ レビュー・口コミ管理機能
機能名：レビュー管理
概要：利用後の口コミや評価を収集・確認し、Web掲載やサービス改善に活用する。
優先度：Should
⑧ 売上分析・レポート機能
機能名：売上分析
概要：予約数、来店数、購入率、再購入率などを可視化し、人気プランや課題を分析できる機能。
優先度：Should
⑨ スタッフ管理機能
機能名：スタッフ管理
概要：担当スタッフのシフト、対応可能枠、予約割当を管理し、現場運営を効率化する。
優先度：Should
⑩ クーポン・販促管理機能
機能名：販促管理
概要：クーポン発行、キャンペーン設定、リピーター向け特典などを管理し、再来店や再購入を促進する。
優先度：Could
⑪ 問い合わせ管理機能
機能名：問い合わせ管理
概要：予約前後の質問や変更依頼を一元管理し、対応漏れを防ぐ機能。
優先度：Could
⑫ 権限管理機能
機能名：権限管理
概要：管理者、店舗スタッフ、EC担当など役割ごとに閲覧・編集できる範囲を設定する。
優先度：Could
まとめ

最優先で必要なのは、
予約管理 / 顧客管理 / 香りレシピ管理 / 在庫管理 / 注文管理 です。

この5つがあると、来店体験の運営と体験後の継続購入の両方を支えられます。



| 機能名     | 概要                                  | 優先度    |
| ------- | ----------------------------------- | ------ |
| 予約管理    | 来店日時・人数・コース・空き枠を管理し、予約変更やキャンセル対応を行う | Must   |
| 顧客管理    | 顧客情報（国籍・連絡先・利用履歴・購入履歴）を一元管理する       | Must   |
| 香りレシピ管理 | 体験で作成した香りの配合データを保存し、再制作や再購入に活用する    | Must   |
| 在庫管理    | 香料・容器などの在庫を管理し、欠品防止や発注判断に活用する       | Must   |
| 注文管理    | ECでの再購入注文を管理し、配送・決済状況を確認できる         | Must   |
| 多言語対応管理 | メール・案内文・一部画面を多言語で管理し、外国人対応を強化する     | Should |
| レビュー管理  | 利用者の口コミ・評価を収集・管理し、改善や集客に活用する        | Should |
| 売上分析    | 予約数・売上・再購入率などを可視化し、経営判断に活用する        | Should |
| スタッフ管理  | シフト・対応枠・予約割当を管理し、運営効率を向上させる         | Should |
| 販促管理    | クーポンやキャンペーンを設定し、再来店・再購入を促進する        | Could  |
| 問い合わせ管理 | 顧客からの問い合わせや変更依頼を一元管理する              | Could  |
| 権限管理    | 管理者・スタッフごとに閲覧・編集権限を設定する             | Could  |

「Must機能により基本運営を成立させ、Should機能で顧客体験と売上を向上、Could機能で長期的な成長を支援する設計とした」

顧客を中心に、予約・体験レシピ・EC再購入を一元管理する構造とした。特に香りレシピを顧客情報と連携させることで、体験後も継続購入につながる仕組みを設計した。
