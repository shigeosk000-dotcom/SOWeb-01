# VS Code + Cline + Gemini で Spring Boot 改修を進めるための実務ガイド

## 目的

このドキュメントは、VS Code 上で **Cline + Gemini** を使い、Spring Boot プロジェクトの **バグ修正** や **仕様変更** を、できるだけ少ない往復で安全に進めるための実務向け手順とテンプレートをまとめたものです。

特に次を重視します。

- リクエスト数を抑える
- 無駄な再試行を減らす
- 最小差分で改修する
- テスト更新まで含めて AI に支援させる
- 人間レビューしやすい形で進める

---

# 1. 全体方針

## 基本方針

- AI に細かく 1 ステップずつ聞かない
- ただし、作業は段階的に分ける
- 毎回長い前提を貼らない
- プロジェクトルールはファイル化して固定する
- 無関係なリファクタリングを避ける
- 最後は必ず人間が差分レビューする

## 推奨する進め方

1. まず影響範囲だけ調査
2. 次に最小差分の修正計画
3. その後に実装
4. 関連テストを更新
5. 変更内容を要約
