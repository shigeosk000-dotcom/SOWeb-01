# AI_RULES

## Goal
Spring Boot プロジェクトの改修を、最小差分・低コスト・高再現性で進める。

## Global Rules
- 既存コードスタイルを維持する
- コメントを増やしすぎない
- 例外は GlobalExceptionHandler に統一する
- 既存アーキテクチャを尊重する
- 無関係なリファクタリングをしない
- 変更は最小差分にする
- まず影響範囲を整理してから実装する
- 実装時は関連テストも更新する
- 既存の命名規則、例外処理、ログ方針に従う
- 不明点は推測せず、コードから確認できる範囲で判断する
- public API の変更時は README / API docs も更新する
- 不明点は推測せず、コードから確認できる範囲で判断できない場合は指示者に問い合わせる

## Spring Boot Rules
- Controller は薄く保つ
- Service にビジネスロジックを置く
- Repository はデータアクセスに限定する
- DTO と Entity を不用意に混在させない
- 既存の GlobalExceptionHandler があればそれに合わせる
- validation は既存の方式に合わせる
- トランザクション境界は既存ルールに従う
- JPA Entity の直接返却を避ける
- N+1 が起きそうなら確認する

## Output Rules
- 出力は簡潔にする
- 毎回長文説明は不要
- 必要なときだけ理由を書く
- 修正時は以下の順で出す
  1. 影響範囲
  2. 実装計画
  3. 変更ファイル
  4. テスト観点
  5. 残リスク
