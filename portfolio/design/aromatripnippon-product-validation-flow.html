Product Validation Flow / Bean Validation + Service Rules

AromaTripNippon 管理機能・商品登録バリデーション処理フロー

商品登録フォーム送信時の2段階バリデーションをASCII図とIF-THEN-ELSE疑似コードで整理します。 第1段階は@ValidによるBean Validation、第2段階はServiceでの業務ロジックバリデーションです。 どちらのエラーもBindingResultに集約し、商品フォームへ戻してエラー表示します。

POST /management/products @Valid Product BindingResult ProductService product-form.html

1. バリデーション観点

1段階目: Bean Validation

  • @Valid @ModelAttribute ProductでController到達時に自動検証する。
  • productNameは@NotBlank、@Size(max=255)で検証する。
  • priceは@NotNull、@Positiveで検証する。
  • descriptionは@Size(max=1000)で検証する。

BindingResult

  • Bean Validationの結果はBindingResult errorsに入る。
  • errors.hasErrors()がtrueなら保存せず商品フォームへ戻す。
  • 戻る前にカテゴリ選択肢を再取得してmodelへセットする。

2段階目: Service業務チェック

  • カテゴリIDが存在し、有効かを確認する。
  • 削除済み商品や既存商品との重複名を確認する。
  • 公開商品として成立するか、価格・カテゴリなどの業務条件を確認する。

登録処理

  • 業務エラーはbindingResult.rejectValue()またはreject()で追加する。
  • エラーがなければカテゴリを設定し、商品と在庫初期データを保存する。
  • 登録後は監査ログを記録し、商品詳細へリダイレクトする。

3. IF-THEN-ELSE形式の疑似コード

// 商品登録バリデーション処理の疑似コード
FUNCTION createProduct(product, bindingResult, categoryId, principal, model)

  // 1段階目: @Valid による自動バリデーション
  // Controller呼び出し前に Product の Bean Validation が実行され、結果が BindingResult に入る

  IF bindingResult.hasErrors() THEN
    model に有効カテゴリ一覧を再セット
    RETURN 商品登録画面（入力値 + Bean Validationエラー表示）
  END IF

  // 2段階目: Serviceでの業務ロジックバリデーション
  businessErrors = ProductService.validateForCreate(product, categoryId)

  IF businessErrors.categoryNotFound THEN
    bindingResult.rejectValue("category", "product.category.invalid",
                              "有効なカテゴリを選択してください")
  END IF

  IF businessErrors.duplicateProductName THEN
    bindingResult.rejectValue("productName", "product.productName.duplicate",
                              "同じ商品名の商品が既に登録されています")
  END IF

  IF businessErrors.invalidPublishedCondition THEN
    bindingResult.reject("product.publish.invalid",
                         "公開する商品はカテゴリ・価格・説明内容を確認してください")
  END IF

  IF bindingResult.hasErrors() THEN
    model に有効カテゴリ一覧を再セット
    RETURN 商品登録画面（入力値 + 業務エラー表示）
  END IF

  // 登録処理
  category = ProductCategoryRepository.findActiveById(categoryId)
  product.category = category

  inventoryItem = InventoryItem()
  inventoryItem.itemName = product.productName
  inventoryItem.englishName = product.englishName
  inventoryItem.category = category.categoryName
  inventoryItem.unit = defaultUnit(category.categoryName)
  inventoryItem.stockQuantity = 0
  inventoryItem.thresholdQuantity = 0

  InventoryItemRepository.save(inventoryItem)
  savedProduct = ProductRepository.save(product)
  AuditService.record(principal, "CREATE", "products", savedProduct.id, "商品を作成")

  RETURN リダイレクト("/management/products/" + savedProduct.id)

END FUNCTION


// Service側の業務ロジックバリデーション例
FUNCTION validateForCreate(product, categoryId)

  result = new BusinessValidationResult()

  category = ProductCategoryRepository.findById(categoryId)

  IF category が null OR category.deletedAt が null ではない OR category.active が false THEN
    result.categoryNotFound = true
  END IF

  duplicate = ProductRepositoryで同名・未削除の商品を検索(product.productName)

  IF duplicate が存在する THEN
    result.duplicateProductName = true
  END IF

  IF product.published が true AND product.description が空 THEN
    result.invalidPublishedCondition = true
  END IF

  RETURN result

END FUNCTION

4. エラーハンドリング整理

段階 チェック内容 エラー時の処理
Bean Validation 必須、文字数、価格の正数などEntity制約 BindingResultに自動格納し、商品フォームへ戻す。
Service業務チェック カテゴリ有効性、重複商品名、公開条件など rejectValue()またはreject()でBindingResultに追加し、商品フォームへ戻す。
画面再表示 エラー表示と入力値保持 categoriesを再セットし、management/product-formを返す。
登録成功 全チェック通過 商品・在庫初期データを保存し、監査ログ記録後に商品詳細へ遷移する。
